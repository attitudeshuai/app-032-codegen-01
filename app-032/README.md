# 花灯骨架放样与蒙面裁片 · Lantern Frame Lofting

纯前端工具：选灯型 → 填直径/高度/收口 → 出「每根竹篾截多长、弯什么角度」的骨架件表、带缝份的蒙面裁片、以及可 100% 打印的 1:1 放样图与备料单。无后端、无网络请求，断网可用。

## 技术栈

- Vue 3（`<script setup>` 单文件组件）+ TypeScript + Vite 6
- 状态：Vue 自带 `ref / reactive / computed / watch`（无 Pinia / Vuex）
- 额外依赖仅 `vue-router` 4（规格书要求的 6 个路由）
- 手写 CSS；无 UI 组件库、无图表库、无游戏引擎/物理库
- 字体、灯型数据包（`src/data/lantern-types.json`）全部本地打包，无外网 CDN

## 竹篾配切下料（`/cutting`）

按库里现有竹篾给订单配切，解决「长篾截短、短篾不够用」：

- **录入**：库存竹篾按长度（整数 mm）+ 根数登记，同长自动合并计数；订单填几种灯各做几盏（灯样复用本机灯样库的骨架件表）。
- **取整规则**：每段下料长 =（净长 + 绑扎余量合计）**按毫米向上取整**；残料能否接下一件只用取整后的整数长度判；长度记 mm，备料总量折 m（3 位小数）。
- **两条互斥路线**：`先保长件（省料）`= BFD + 分支限界精确装箱（可行域内废料最少）；`先凑短件（省时）`= Next-Fit 不回头翻料（试配/刀数/取篈工时最少）。采用新路时旧版连同已导出备料单、本机存档**一起作废**：已截段按 R* 料号退回料架重登，旧留用余料按 U* 料号转普通库存，留用记录失效；并写明被放弃路线在材料与工时上让出的代价。
- **最大化盏数**：订单按灯种穷举可行盏数向量，只接受整盏配得齐的方案；挑不全时逐件列清是**长度不够**（库内最长篈短于件长）还是**根数不够**，并给添料根数/长度。
- **三处同源**：骨架构件表（每段标注取自哪根篈、同料号第几根、第几段、本根剩余）、备料/材料页（还要添几根/多长）、本机存档台账（留用余料/未动用整篈/版本历史）全部从同一个 `CutPlan` 取数；三份 CSV 导出同样如此。守恒自检 CUT-C1~C5 按整数 mm 逐根逐毫米核对（构件表 Σ截取长 = 材料页用掉 = 动用原长 − 废料 − 留用；三处剩余逐根一致，差 1mm 即报红）。
- **整批重算 diff**：改盏数或换库存即作废旧采用版重算，并列出三处变化——构件表里哪几根件的来源料号/段号换了、材料页哪几项规格与根数变了、存档里上次留用的哪几根这次不再留用。

## 启动

```bash
npm install
npm run dev        # http://127.0.0.1:5173
npm run build      # vue-tsc --noEmit && vite build
npm run preview
```

## Docker 构建

```bash
docker compose build
docker compose up -d            # http://localhost:8112
curl http://localhost:8112/healthz
docker compose down
```

多阶段：`node:20-alpine` 构建 → `nginx:1.27-alpine` 只托管 `dist/` 与 `nginx.conf`（SPA 回退、哈希资源 immutable、index.html no-cache、gzip、SVG MIME、`/healthz` 健康检查）。
