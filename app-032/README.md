# 花灯骨架放样与蒙面裁片 · Lantern Frame Lofting

纯前端工具：选灯型 → 填直径/高度/收口 → 出「每根竹篾截多长、弯什么角度」的骨架件表、带缝份的蒙面裁片、以及可 100% 打印的 1:1 放样图与备料单。无后端、无网络请求，断网可用。

## 技术栈

- Vue 3（`<script setup>` 单文件组件）+ TypeScript + Vite 6
- 状态：Vue 自带 `ref / reactive / computed / watch`（无 Pinia / Vuex）
- 额外依赖仅 `vue-router` 4（规格书要求的 6 个路由）
- 手写 CSS；无 UI 组件库、无图表库、无游戏引擎/物理库
- 字体、灯型数据包（`src/data/lantern-types.json`）全部本地打包，无外网 CDN

## 配切下料作坊（`/cut`）

按库里**现有**竹篾给一批花灯配切，不再拿尺子一根根比：

- **录入**：库存竹篾按「长度 × 根数」入库（每根一条料号 M0001…）；订单按「灯样 × 盏数」或散件行填，灯样构件直接从骨架件表带出净长与绑扎余量。
- **取整口径（唯一）**：每段截取长 = `ceil(净长 + 余量处数 × 每处绑扎余量)` 整毫米；库存容量 = `floor(原长)`；残料能不能接下一件一律拿**取整后的整数**比（`残料 ≥ 本批最短截取长` 才留用，否则明确判废），绝不用未取整小数比。长度 mm，备料总量折 m（3 位小数，精确到 1mm）。
- **两条互斥路线，只能选一条**：`省料·先保长件`（废料最少）/ `省时·短件凑齐`（动用根数、上下料、归架最少）。两版都给出废料 mm、留用 mm、动用根数、工时（工分）对比，并写清被放弃那条在材料与工时上让出的代价。小批量走精确分支限界（求得真正最优），大批量自动退回多起点启发式 + 局部搜索。
- **三处同源**：骨架构件表（每件标「取自哪根篾·第几段·起点」，同种件合并计数）、备料料架页（每根库存篾状态/截用/残料 + 添几根添多长）、本机灯样存档（`localStorage`）都从**同一份已提交方案快照**取数，抬头同方案号/批次/内容指纹；逐篾 `容量=段合计+残料`、全批 `段合计=用掉总量`，差 1mm 也在表里暴露。
- **整批复算与三处差异**：改盏数或换库存批次号前进，列出①构件表里哪几件的来源段换了②材料页添料规格/根数变化③存档里上次留用的哪几根余料被续截/不再留用。
- **换路线作废重来**：旧版方案 + 已导出的三份清单（构件表/备料料架/添料单）+ 本机存档一起标记作废，按旧版已截好的各段与残料**退回料架以新料号重新登记**（旧料号保留来源痕迹），旧版余料留用记录随之失效，再按新路线提交。导出只认当前活跃方案，批次落后或指纹不符会被拒绝。
- **缺料说清**：任何库存都短于某件 →「长度不够」（报库内最长）；长度够但总量/根数不足 →「根数不够」；添料单同规格合并计数，并据此算各行能做几盏。

域代码在 `src/core/cut/`（`cutpack.ts` 算法 / `store.ts` 料架订单存档作废 / `diff.ts` 三处差异 / `exporter.ts` 三份 CSV / `types.ts` 模型），页面 `src/views/CutView.vue`，路由 `/cut`。
